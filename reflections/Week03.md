1.2 Map out, step by step, what re-work is triggered in a waterfall process (docs, sign-offs, re-testing)
Changing a requiremnet at the 4 month stage with a waterfall model would require significant rework due to the requirements and design being already approved. The following changes would be necessary for the waterfall model at this stage.

Requirements - Add the feature *ordering from multiple restaurants* to the requirments documnet.

Design - Change the system design and database to support the new feature.

Implementation - Update the exising code.

Testing - Retest to ensure all existing features still work.

Approval - Gain any design and change approvals before continuing.

1.3 Now assume the same team was working in 2-week increments — re-trace the impact
With the Agile approach the project will be developed in small increments.  

When the university requests the new feature, the team would:

Add the requirement to the Product Backlog - Record the new feature as user stories.

Prioritise the requirement - Work with the customer to decide how important the new feature is compared with existing work.

Plan the next iteration - Select the new user stories for an upcoming two-week iteration, based on team capacity.

Implement the changes - Update the database, payment processing, kitchen notifications and checkout interface.

Test the changes - Test the new functionality and check that existing features still work.

Gather feedback - Demonstrate the working increment to the customer and make further improvements if necessary.
